# 一期数据库表设计：橡胶件制造 ERP

## 1. 设计范围与约定

本文为一期 MVP 的逻辑数据库设计，采用 PostgreSQL。物理实现建议使用 Prisma 管理迁移，但关键库存过账在数据库事务中完成。

- 主键统一为 `uuid`；业务单据同时使用可读的 `document_no`。
- 一期实际为单公司、单仓库，但交易、主数据、库存表保留 `company_id` 和 `warehouse_id`，不将其写死。
- 金额、单价、汇率、数量使用 `numeric`，禁止浮点数；日期使用 `date`，审计时间使用带时区的 `timestamptz`。
- 所有业务表都有 `created_at`、`created_by`、`updated_at`、`updated_by`；已过账记录不物理删除。
- 枚举值在代码中受限，并在本文注明；可配置字典另由 `system_settings` 和主数据表维护。
- 外键采用 `uuid`，用于跨模块追溯；单据行在过账时保存必要快照，避免主数据后续修改影响历史。

## 2. 领域关系概览

```text
users --< user_roles >-- roles --< role_permissions >-- permissions
materials --< bom_items >-- boms --< production_orders
suppliers --< purchase_orders --< purchase_order_lines >-- materials
customers --< sales_orders --< sales_order_lines >-- materials
production_orders --< production_materials >-- materials
production_orders --< inventory_transactions >-- inventory_batches
inventory_batches --< inventory_transactions
inventory_balances = inventory_transactions 的当前汇总读模型
document_files --< import_tasks --< import_task_items
```

## 3. 平台与权限表

### 3.1 `companies`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 公司主键 |
| `code` | varchar(30) UQ | 公司编码；一期预置 `MAIN` |
| `name` | varchar(120) | 公司名称 |
| `base_currency_code` | char(3) FK | 固定为 `CNY` |
| `is_active` | boolean | 启用状态 |

### 3.2 `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 用户主键 |
| `username` | varchar(64) UQ | 登录名 |
| `password_hash` | varchar(255) | 强哈希后的密码 |
| `display_name` | varchar(80) | 显示姓名 |
| `mobile` | varchar(30) nullable | 手机端联系信息 |
| `is_active` | boolean | 禁用后不可登录 |
| `last_login_at` | timestamptz nullable | 最近登录时间 |

### 3.3 `roles`、`permissions`、`user_roles`、`role_permissions`

一期不固定采购、销售、仓库、生产等角色。角色通过权限组合定义。

| 表 | 关键字段与约束 |
| --- | --- |
| `roles` | `id`、`code` UQ、`name`、`description`、`is_system`、`is_active`；系统管理员角色不可删除。 |
| `permissions` | `id`、`code` UQ、`name`、`module`、`action`；例如 `bom.view`、`bom.export`、`inventory.post`、`inventory.reverse`。 |
| `user_roles` | `user_id` FK、`role_id` FK、`company_id` FK，联合唯一 `(user_id, role_id, company_id)`。 |
| `role_permissions` | `role_id` FK、`permission_id` FK，联合唯一 `(role_id, permission_id)`。 |

### 3.4 `system_settings`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 主键 |
| `company_id` | uuid FK | 公司维度 |
| `setting_key` | varchar(100) | 例如 `inventory.reversal_window_days` |
| `setting_value` | jsonb | 字符串、数值、布尔值或结构化配置 |
| `description` | varchar(255) | 配置说明 |

唯一约束：`(company_id, setting_key)`。冲销时限由 `inventory.reversal_window_days` 读取，不在代码中写死。

### 3.5 `audit_logs`

字段：`id`、`company_id`、`actor_user_id`、`action`、`resource_type`、`resource_id`、`before_data jsonb`、`after_data jsonb`、`request_id`、`ip_address`、`user_agent`、`created_at`。

索引：`(resource_type, resource_id, created_at desc)`、`(actor_user_id, created_at desc)`。配方查看、导出、发布、库存过账和冲销必须写入本表。

## 4. 财务口径与基础主数据表

### 4.1 `currencies`、`exchange_rates`、`tax_rates`

| `exchange_rates` | `id`、`company_id`、`currency_code` FK、`rate_date date`、`rate_to_cny numeric(18,8)`、`source=MANUAL`、`is_active`；唯一 `(company_id, currency_code, rate_date)`。 |
| `tax_rates` | `id`、`company_id`、`code`、`name`、`rate numeric(5,4)`、`effective_from`、`effective_to nullable`、`is_active`；唯一 `(company_id, code, effective_from)`。预置 13%、9%、6%、3%、0%。 |

### 4.2 `units`、`material_categories`

| 表 | 关键字段与规则 |
| --- | --- |

| `material_categories` | `id`、`company_id`、`parent_id nullable`、`code`、`name`、`is_active`；用于原材料、辅料、半成品、成品等树形分类。 |

### 4.3 `warehouses`、`locations`

| 表 | 关键字段与规则 |

| `locations` | `id`、`warehouse_id`、`code`、`name`、`location_type`、`is_active`；预置 `RAW`、`QUARANTINE`、`PRODUCTION`、`FINISHED_GOODS`、`RETURN`。唯一 `(warehouse_id, code)`。 |

### 4.4 `materials`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 物料主键 |
| `company_id` | uuid FK | 公司 |
| `code` | varchar(50) | 物料编码，联合唯一 `(company_id, code)` |

### 4.5 `customers`、`suppliers`

均包含：`id`、`company_id`、`code`、`name`、`contact_name`、`mobile`、`email`、`address`、`default_currency_code`、`default_tax_rate_id`、`is_active`。各自以 `(company_id, code)` 唯一。

## 5. 配方与生产表

### 5.1 `boms`、`bom_items`

| 表 | 关键字段与规则 |
| --- | --- |
| `boms` | `id`、`company_id`、`output_material_id`、`version_no`、`status`（`DRAFT`、`PENDING_RELEASE`、`EFFECTIVE`、`DISABLED`）、`standard_output_qty`、`output_unit_id`、`effective_from`、`effective_to`、`confidential_level`、`released_by`、`released_at`。唯一 `(company_id, output_material_id, version_no)`。同一成品在同一日期只允许一份有效 BOM。 |
| `bom_items` | `id`、`bom_id`、`line_no`、`input_material_id`、`required_qty`、`unit_id`、`loss_rate numeric(5,4)`、`remark`；唯一 `(bom_id, line_no)`。 |

授权规则：任何读取 `bom_items` 的 API 均检查 `bom.view`；导出检查 `bom.export`；发布检查 `bom.release`。

### 5.2 `production_orders`、`production_output_lines`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` / `document_no` | uuid / varchar UQ | 主键与生产单号 |
| `company_id` / `warehouse_id` | uuid FK | 组织与仓库 |
| `production_type` | enum | `MAKE_TO_ORDER`、`MAKE_TO_STOCK` |
| `sales_order_id` / `sales_order_line_id` | uuid nullable | 按订单生产时关联 |
| `output_material_id` | uuid FK | 产出物料 |
| `bom_id` / `bom_version_snapshot` | uuid / varchar | 锁定 BOM 与版本快照 |
| `planned_qty` / `completed_qty` / `scrap_qty` | numeric | 计划、完工、报废数量 |
| `unit_id` | uuid FK | 产出单位 |
| `planned_date` | date | 计划日期 |
| `target_location_id` | uuid FK | 产出库位 |
| `status` | enum | `DRAFT`、`RELEASED`、`IN_PROGRESS`、`COMPLETED`、`CLOSED`、`VOIDED` |
| `remark` | text nullable | 备注 |

`production_orders` 保留首行产出物料、BOM、数量和单位字段作为兼容摘要；实际多物料排产以 `production_output_lines` 为准。产出行字段：`id`、`production_order_id`、`line_no`、`material_id`、`bom_id`、`bom_version_snapshot`、`planned_qty`、`unit_id`、`source_sales_order_line_id nullable`，唯一 `(production_order_id, line_no)`。

一期不建立工艺路线、工序、工序任务或报工表。生产订单通过领料、退料、完工和报废的库存事务完成闭环。

### 5.3 `production_materials`

生产订单展开的理论用料快照。字段：`id`、`production_order_id`、`production_output_line_id nullable`、`line_no`、`material_id`、`required_qty`、`issued_qty`、`returned_qty`、`unit_id`、`loss_rate`、`remark`。每组理论用料通过 `production_output_line_id` 关联对应产出行；唯一 `(production_order_id, line_no)`。

## 6. 采购与销售表

### 6.1 `purchase_orders`、`purchase_order_lines`

| 表 | 关键字段 |
| --- | --- |
| `purchase_orders` | `id`、`document_no` UQ、`company_id`、`supplier_id`、`order_date`、`expected_date`、`currency_code`、`exchange_rate`、`exchange_rate_date`、`status`（`DRAFT`、`SUBMITTED`、`PARTIALLY_RECEIVED`、`COMPLETED`、`CLOSED`、`VOIDED`）、金额汇总快照、`source_file_id nullable`。 |
| `purchase_order_lines` | `id`、`purchase_order_id`、`line_no`、`material_id`、`description_snapshot`、`ordered_qty`、`received_qty`、`unit_id`、`tax_rate_snapshot`、`unit_price_ex_tax`、`amount_ex_tax`、`tax_amount`、`amount_inc_tax`、`amount_cny`。 |

唯一：`(purchase_order_id, line_no)`。采购入库以 `inventory_transactions.source_document_type = PURCHASE_RECEIPT` 与采购行关联，更新 `received_qty`。

### 6.2 `sales_orders`、`sales_order_lines`

| 表 | 关键字段 |
| --- | --- |
| `sales_orders` | `id`、`document_no` UQ、`company_id`、`customer_id`、`order_date`（默认当天）、`expected_shipment_at`、`actual_shipment_at`、`currency_code`、`exchange_rate`、`exchange_rate_date`、`status`、金额汇总快照、`source_file_id nullable`。 |
| `sales_order_lines` | `id`、`sales_order_id`、`line_no`、`material_id`、`description_snapshot`、`ordered_qty`、`shipped_qty`、`reserved_qty`、`unit_id`、`tax_rate_snapshot`、价格与金额字段。 |

唯一：`(sales_order_id, line_no)`。如启用预留，使用 `stock_reservations` 锁定可用库存。

## 7. 库存、批次与成本表

### 7.1 `inventory_batches`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 批次主键 |
| `company_id` / `material_id` | uuid FK | 公司与物料 |
| `batch_no` | varchar(80) | 内部批次号，唯一 `(company_id, material_id, batch_no)` |
| `supplier_batch_no` | varchar(80) nullable | 供应商批号 |
| `production_date` / `expiry_date` | date | 均为存货批次关键字段 |
| `batch_status` | enum | `AVAILABLE`、`LOCKED`、`FROZEN`、`QUARANTINE`、`EXPIRED` |
| `source_document_type` / `source_document_id` | varchar / uuid | 来源采购入库或生产完工 |
| `supplier_id` | uuid nullable | 外购批次的供应商 |
| `unit_cost_cny` | numeric(18,6) | 当前批次成本快照，供追溯展示；一期总账成本仍以移动平均为准 |

索引：`(company_id, material_id, expiry_date, batch_status)`，供 FEFO 推荐与临期预警使用。

### 7.2 `inventory_transactions`

库存事务是库存事实账。任何数量和成本变化必须追加到本表。

| 字段 | 说明 |
| --- | --- |
| `id`、`company_id`、`transaction_no` UQ | 主键、公司、流水号 |
| `transaction_type` | `PURCHASE_RECEIPT`、`PURCHASE_RETURN`、`SALES_SHIPMENT`、`SALES_RETURN`、`PRODUCTION_ISSUE`、`PRODUCTION_RETURN`、`PRODUCTION_RECEIPT`、`SCRAP`、`TRANSFER_OUT`、`TRANSFER_IN`、`STOCKTAKE_GAIN`、`STOCKTAKE_LOSS`、`REVERSAL` |
| `material_id`、`batch_id`、`warehouse_id`、`location_id` | 库存粒度 |
| `quantity_delta` | 正数入库，负数出库 |
| `unit_id`、`unit_cost_cny`、`amount_delta_cny` | 数量与成本影响 |
| `occurred_at`、`posted_at` | 业务发生与过账时间 |
| `source_document_type`、`source_document_id`、`source_document_line_id` | 来源单据 |
| `reversal_of_transaction_id nullable` | 冲销指向原事务 |
| `reason_code`、`remark`、`posted_by` | 原因、备注、操作人 |

约束和索引：`quantity_delta <> 0`；`(material_id, warehouse_id, location_id, batch_id, posted_at)`；`(source_document_type, source_document_id)`；`(reversal_of_transaction_id)` 唯一且非空时防止重复冲销。

### 7.3 `inventory_balances`

当前库存读模型，粒度为 `(company_id, warehouse_id, location_id, material_id, batch_id, unit_id)`，联合唯一。

字段：`on_hand_qty`、`reserved_qty`、`available_qty`、`updated_at`、`version`。其中 `available_qty = on_hand_qty - reserved_qty`，通过事务内更新或计算列保证一致。禁止业务 API 直接编辑本表。

### 7.4 `stock_reservations`

字段：`id`、`company_id`、`sales_order_line_id`、`inventory_balance_id`、`reserved_qty`、`status`（`ACTIVE`、`RELEASED`、`CONSUMED`）、`created_at`、`released_at nullable`。当销售订单启用锁库时创建；发货或关闭订单后释放/消耗。

### 7.5 `cost_records`

一期采用移动加权平均。字段：`id`、`company_id`、`material_id`、`inventory_transaction_id`、`before_qty`、`before_amount_cny`、`in_qty`、`in_amount_cny`、`after_qty`、`after_amount_cny`、`moving_average_cost_cny`、`created_at`。

此表用于成本可追溯和对账；入库事务与成本记录必须在同一数据库事务提交。

## 8. 文件解析、财务流水与导入表

### 8.1 `document_files`

字段：`id`、`company_id`、`original_name`、`storage_key`、`mime_type`、`size_bytes`、`sha256`、`uploaded_by`、`uploaded_at`、`access_level`、`is_deleted`。

文件对象私有存储，下载时始终经过业务权限检查。配方附件需要 `access_level = BOM_CONFIDENTIAL`。

### 8.2 `import_tasks`、`import_task_items`

| 表 | 关键字段 |
| --- | --- |
| `import_tasks` | `id`、`company_id`、`file_id`、`import_type`（`PURCHASE_ORDER`、`PURCHASE_RECEIPT`、`SALES_ORDER`、`SHIPMENT`、`FINANCIAL_FLOW`、`INITIAL_INVENTORY`）、`parser_type`（`XLSX`、`IMAGE_OCR`）、`status`、`created_by`、`created_at`、`completed_at`。 |
| `import_task_items` | `id`、`task_id`、`row_no`、`raw_data jsonb`、`parsed_data jsonb`、`confidence numeric(5,4)`、`validation_errors jsonb`、`status`、`generated_document_id nullable`。 |

解析只创建草稿单据。`generated_document_id` 在草稿生成后记录，严禁由解析任务直接触发库存过账。

### 8.3 `financial_flows`

当前 MVP 物理表为 `cash_flows`：`id`、`document_no`、`company_id`、`occurred_at`、`flow_type`（`INFLOW`/`OUTFLOW`）、`amount`、`currency_code`、`description`、`created_at`。用于现金收入和支出流水。

### 8.4 `reimbursements`

单次费用报销表：`id`、`document_no`、`company_id`、`occurred_at`、`expense_type`、`amount`、`currency_code`、`description`、`created_at`。一期不拆分审批和报销明细。

### 8.5 `bills`

账单表：`id`、`bill_no`、`company_id`、`bill_type`（`RECEIVABLE`/`PAYABLE`）、`status`、`supplier_id nullable`、`customer_id nullable`、`source_document_type`、`source_document_id`、`source_document_no`、`bill_date`、`due_date`、`currency_code`、`amount`、`description`、时间字段。采购订单和销售订单通过 `(source_document_type, source_document_id)` 唯一关联，防止重复生成。

字段：`id`、`company_id`、`flow_no`、`flow_date`、`flow_type`（`RECEIPT`、`PAYMENT`）、`counterparty_name`、`currency_code`、`exchange_rate`、`amount_foreign`、`amount_cny`、`related_document_type nullable`、`related_document_id nullable`、`summary`、`source_file_id`、`status`、`created_by`。

一期只用于导入、查询、标注和单据关联，不执行自动核销或生成财务凭证。

## 9. MVP 物理实现顺序

1. 平台与权限：`companies`、`users`、角色权限、`system_settings`、`audit_logs`。
2. 主数据：币种、汇率、税率、单位、仓库库位、物料分类、物料、客户、供应商。
3. 库存底座：批次、库存事务、库存余额、成本记录。
4. 配方生产：BOM、生产订单、生产订单用料。
5. 采购销售：订单与行项目，收货/发货通过库存事务先完成。
6. 附件导入：文件、解析任务、解析明细、财务流水。

## 10. 关键校验清单

- 存货物料若缺批次、生产日期或到期日期，禁止库存过账。
- 临期批次允许领料和发货并展示提醒；过期、隔离、冻结批次不可用。
- 任何库存余额变动都可回溯到一条或多条库存事务和来源单据。
- 同一库存事务不能被重复提交；同一原事务不能被重复冲销。
- BOM 明细、配方附件和导出任务均在服务端校验权限。
- USD 单据必须保存汇率、汇率日期、外币金额与人民币折算金额；税率和金额快照必须保留在单据行。
- 自建角色修改、系统参数修改、库存过账与冲销均写审计日志。
